# kigit Diff

## How to use

### Arguments
There are numerous ways to use kigit diff with different arguments:

* In order to check uncommited changes to the last commit, use: `kigit diff`
* In order to check uncommited changes of a certain file to the last commit, use: `kigit diff <filename>`
* In order to check the latest commit to an earlier commit, use: `kigit diff <commit>`
* In order to check the changes of only a certain file within the latest commit to the file within an earlier commit, use: `kigit diff <commit> <filename>`
* In order to check the changes between two specific commits, use: `kigit diff <commit> <commit>`
* You can also check changes between branches, tags, or a combination of tags, branches and commits, by using `kigit diff <commit/branch/tag> <commit/branch/tag>`, or simply `kigit diff <commit/branch/tag>`

### Options
In addition to arguments, kigit diff also has multiple different options to work with:

* The option `--show-filename: boolean` lets kigit display the changed components of each file in their own respective row, and adds the filename of each file to the depicted table.
* The option `--output: str` lets the user decide which output to use. THe default is the command line interface that kigit is running in, but json and html are also options.
* The option `--erc-drc-check: boolean` lets kigit perform an erc check on every schematic file and a drc check on the pcb file within the working directory. By default, the checks are stored in rpt files with the same name as the schematic and pcb files. If json or html is selected as the output, it will instead store the checks to a file with the same format.
* The option `--detail: str` causes kigit to show a detailed view of the modified components of Kicad files. `--detail all` will show all details to changed components within the pcb and schematics. You can also specifiy what details to show however. `--detail start` will show the start points of segments in pcb's for example, and `--detail start,end` will show both the start and end points of segments. In general, the usage of detail looks like this: `--detai detail1, detail2, ..`, with the numbered details being specified details of schematic or pcb components. 
* The option `--debug: boolean` enables additional debug options for the kigit output.
